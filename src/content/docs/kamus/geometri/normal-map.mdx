[Tekstur](/kamus/geometri/texture/) yang menyimpan arah [normal](/kamus/geometri/normal/) **per piksel**, bukan per vertex. Saat menghitung cahaya, shader memakai arah dari tekstur ini sebagai ganti normal mesh. Hasilnya, permukaan datar tampak punya tonjolan, goresan, dan lekukan, padahal jumlah segitiganya tidak berubah.

Nilai R, G, B setiap piksel menyimpan komponen X, Y, Z sebuah arah. Karena warna bernilai 0..1 sedangkan arah bernilai −1..1, shader mengubahnya dengan rumus sederhana. Itulah kenapa normal map umumnya berwarna biru keunguan: warna (0,5; 0,5; 1) berarti "lurus ke luar permukaan", alias tidak ada perubahan.

```text title="Pseudocode"
arah = warna_tekstur * 2 - 1        // dari 0..1 menjadi -1..1
normal_akhir = putar_ke_permukaan(arah, normal, tangent)
```

Arah di normal map biasanya relatif terhadap permukaan (*tangent space*), jadi mesh butuh data **tangent** selain normal. Tanpa tangent, normal map tampil salah.

<Aside type="note" title="Analogi">
Lukisan trompe-l'œil di dinding datar: dari depan tampak ada relief, tetapi dindingnya tetap rata. Bedanya, normal map ikut bereaksi saat arah cahaya berubah.
</Aside>

## Di engine

<EngineTabs>
<div slot="unity">

Di pengaturan impor tekstur, set **Texture Type: Normal map**, lalu pasang di slot **Normal Map** material URP/Lit (ada slider untuk kekuatannya). Unity memakai format **Y+** (gaya OpenGL). Unity juga bisa mengubah height map hitam-putih menjadi normal map saat impor.

</div>
<div slot="unreal">

Tekstur dengan Compression Settings **Normalmap**, dihubungkan ke input **Normal** pada Material. Unreal memakai format gaya DirectX (Y−), jadi normal map dari sumber gaya OpenGL perlu dibalik kanal hijaunya.

</div>
<div slot="godot">

`StandardMaterial3D`: aktifkan `normal_enabled`, isi `normal_texture`, dan atur kekuatannya dengan `normal_scale`. Godot memakai format **Y+** (gaya OpenGL). Untuk normal map gaya DirectX, set opsi impor `process/channel_remap/green` ke Green Inverted. Opsi impor `compress/normal_map` (bawaan Detect) membuat Godot mengenali normal map dan mengompresnya dengan format yang cocok. Normal map punya sedikit ongkos performa, terutama di GPU ponsel.

</div>
</EngineTabs>

## Pelajari lebih dalam

Normal map dipakai hampir di setiap game 3D lewat proses **baking**: seniman membuat model resolusi sangat tinggi (jutaan segitiga), lalu detail permukaannya "dipanggang" menjadi normal map untuk model ringan yang dipakai di game. Model ringan tetap tampak detail dari dekat.

Batasnya: normal map hanya mengubah cahaya, bukan bentuk. Siluet objek tetap datar, dan dari sudut sangat miring ilusinya mulai terlihat.

Normal map gaya OpenGL (Y+) dan DirectX (Y−) hanya beda arah kanal hijau. Jika tonjolan tampak seperti cekungan, kemungkinan formatnya tertukar.
