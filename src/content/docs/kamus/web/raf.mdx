Fungsi browser yang memanggil callback-mu sebelum layar digambar ulang, umumnya mengikuti refresh rate monitor. Callback harus memanggil `requestAnimationFrame` lagi agar membentuk loop. Di kebanyakan browser rAF dijeda saat tab di latar belakang (hemat baterai), tidak seperti `setInterval` yang tetap berjalan walau diperlambat.

```js
function tick() {
  // update...
  renderer.render(scene, camera)
  requestAnimationFrame(tick)
}
requestAnimationFrame(tick)
```

## Pelajari lebih dalam

Callback requestAnimationFrame dijalankan sekali per pembaruan tampilan, **sebelum** browser menghitung ulang style dan layout lalu menggambar. Karena itu perubahan DOM dan render WebGL di dalamnya muncul di frame yang sama.

Browser bebas menahan rAF: dijeda di tab latar belakang dan di iframe yang tersembunyi. Refresh rate monitor juga beragam, misalnya 60, 75, 120, atau 144 Hz. Jangan pernah mengandalkan "rAF pasti dipanggil 60× per detik". Selalu gunakan waktu sebenarnya ([Delta Time](/kamus/dasar/delta-time/)).
