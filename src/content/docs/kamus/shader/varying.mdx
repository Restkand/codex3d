Nilai yang dikirim dari [vertex shader](/kamus/shader/vertex-shader/) ke [fragment shader](/kamus/shader/fragment-shader/). Satu segitiga hanya punya tiga titik tetapi bisa menutupi ratusan piksel, jadi saat [rasterization](/kamus/shader/pipeline-raster/) GPU mencampur nilai dari ketiga titik secara halus untuk setiap piksel.

Karena itu, menghitung sesuatu per vertex lalu mengirimnya lewat varying lebih murah daripada menghitungnya per piksel. Hasilnya sedikit kurang akurat, tetapi untuk efek yang berubah perlahan, seperti gradasi, sering tidak terlihat bedanya.

## Di engine

<EngineTabs>
<div slot="unity">

Di HLSL URP, struct keluaran vertex shader lazim dinamai `Varyings` (dan struct masukannya `Attributes`). Isinya selalu memuat posisi clip space dengan semantik `SV_POSITION`, ditambah data lain yang ingin kamu teruskan.

Shader Graph: tambahkan blok **Custom Interpolator** di konteks Vertex pada Master Stack, pilih tipe datanya (Float sampai Vector 4) dan beri nama. Di bagian fragment, baca nilainya dengan node Custom Interpolator. Jumlah interpolator dibatasi perangkat keras, jadi shader dengan terlalu banyak interpolator bisa gagal dikompilasi di sebagian platform.

</div>
<div slot="unreal">

Node **Vertex Interpolator**, atau input **Customized UVs** untuk mengirim nilai UV yang dihitung per vertex.

</div>
<div slot="godot">

Kata kunci `varying`, ditulis di luar fungsi. Nilainya diisi di `vertex()` dan dibaca di `fragment()`:

```glsl title="gradasi.gdshader"
shader_type spatial;

varying float tinggi;

void vertex() {
    tinggi = VERTEX.y;
}

void fragment() {
    ALBEDO = vec3(tinggi);
}
```

Tambahkan `flat` (misalnya `varying flat int id;`) jika nilainya tidak boleh dicampur antar-titik. Bawaannya `smooth`, yaitu dicampur dengan koreksi perspektif.

</div>
</EngineTabs>

<Aside type="note" title="Di Lab (Three.js)">
Hologram Lab mengirim `vNormal` dan `vViewDir` dari vertex ke fragment shader untuk menghitung Fresnel. Lihat `src/experiment/shaders/hologram/vertex.glsl`.
</Aside>
