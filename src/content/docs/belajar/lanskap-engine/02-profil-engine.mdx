<Aside type="note" title="Setelah pelajaran ini kamu bisa">
- Menyebut sembilan kriteria untuk membandingkan engine, dan alasan setiap kriteria penting.
- Membaca profil Unity, Unreal Engine, Godot, GameMaker, framework dan library web, serta engine buatan sendiri dengan kriteria yang sama.
- Membedakan engine open source, engine dengan kode sumber yang bisa diakses lewat perjanjian, dan engine dengan kode sumber tertutup.
- Mencari fakta engine di dokumentasi resminya dan mencatat versinya.
</Aside>

## Gambaran besar

<Aside type="note" title="Model mental: lembar spesifikasi kendaraan">
Mobil keluarga, truk, dan sepeda motor bisa ditulis di lembar spesifikasi yang sama: kapasitas, bahan bakar, jarak tempuh, dan perawatan. Dengan lembar itu kamu mencocokkan kendaraan dengan kebutuhanmu, misalnya mengangkut lima orang atau dua ton barang.
</Aside>

Pelajaran ini berisi lembar spesifikasi untuk engine yang paling sering kamu temui. Setiap profil memakai sembilan kriteria yang sama, dengan urutan yang sama, supaya bisa dibandingkan baris demi baris. Komponen engine dan empat model scene sudah dibahas di [Pelajaran 1](/belajar/lanskap-engine/01-apa-itu-engine/), jadi di sini cukup ditautkan.

Dua hal sengaja tidak dibahas. Harga, royalti, dan ambang pendapatan dibahas di [Pelajaran 3 tentang lisensi dan model biaya](/belajar/lanskap-engine/03-lisensi/), dengan sumber yang diperiksa ketat. Cara menimbang kriteria untuk proyekmu dibahas di [Pelajaran 4, Kriteria memilih engine](/belajar/lanskap-engine/04-kriteria-memilih/).

Fakta di sini diambil dari dokumentasi dan situs resmi setiap engine pada 30 Oktober 2026: dokumentasi Godot versi stabil 4.7, manual Unity 6.0 (6000.0 LTS), manual GameMaker cabang monthly dengan rilis LTS 2026, Three.js r187, Phaser 4.2.1, dan Babylon.js 9.0. Engine berubah cepat, jadi cocokkan dengan versi yang kamu pakai.

## Sembilan kriteria

| Kriteria | Pertanyaan yang dijawab |
| --- | --- |
| **Bahasa scripting** | Dalam bahasa apa kodemu ditulis? Ada pilihan visual tanpa kode? |
| **Model scene** | Bagaimana isi dunia game disusun? Lihat [empat model di Pelajaran 1](/belajar/lanskap-engine/01-apa-itu-engine/#cara-engine-menyusun-isi-dunia). |
| **Editor dan alur kerja** | Alat apa yang dipakai sehari-hari untuk menyusun scene, menulis kode, dan menguji? |
| **2D dan 3D** | Apakah alat dan fiturnya ditujukan untuk 2D, 3D, atau keduanya? |
| **Platform target** | Ke platform apa game bisa dibuat build-nya, menurut halaman resmi? |
| **Akses kode sumber** | Open source (dengan nama lisensinya), bisa diakses lewat perjanjian, atau tertutup? |
| **Cocok untuk tim yang** | Kebutuhan tim seperti apa yang dilayani dengan baik oleh engine ini? |
| **Ekosistem** | Toko aset, plugin, dan dokumentasi apa yang tersedia? |
| **Dipakai untuk** | Contoh game, hanya jika halaman resmi engine atau pengembangnya menyebutnya. Kalau tidak ada, baris ini dibiarkan kosong. |

Untuk platform, ada satu ketentuan yang berlaku umum. Konsol seperti PlayStation, Xbox, dan Nintendo Switch adalah platform tertutup. Untuk merilis game di sana, studio biasanya harus terdaftar dan disetujui pemilik platform, lalu mendapat akses ke SDK dan perangkat pengembangan, apa pun engine-nya. Jadi kalau sebuah engine bisa membuat build konsol, itu belum berarti timmu otomatis boleh merilis di sana.

## Unity

Unity adalah engine dari Unity Technologies yang dipakai untuk game 2D dan 3D. Logika game ditulis dengan C# sebagai komponen pada GameObject.

| Kriteria | Unity |
| --- | --- |
| Bahasa scripting | C#. Paket **Visual Scripting** menyediakan graf berbasis node untuk menyusun logika tanpa menulis kode C#, dan punya API untuk membuat node sendiri. |
| Model scene | [GameObject dan komponen](/belajar/lanskap-engine/01-apa-itu-engine/#gameobject-dan-komponen). Paket Entities menyediakan [ECS](/belajar/lanskap-engine/01-apa-itu-engine/#ecs-entitas-komponen-sistem) di samping GameObject. |
| Editor dan alur kerja | Unity Editor dengan jendela Scene, Hierarchy, dan Inspector. Game diuji di Play mode, lalu build dibuat per platform lewat Build Profiles ([Pelajaran 1](/belajar/lanskap-engine/01-apa-itu-engine/#runtime-dan-editor-apa-yang-ikut-ke-build)). |
| 2D dan 3D | Keduanya. Manual punya bagian khusus 2D (sprite, Tilemap, physics 2D), dan sebagian besar dokumentasi berlaku untuk keduanya. |
| Platform target | Manual Unity 6.0 mendaftar Android, iOS, Windows, macOS, Linux, Web, tvOS, Universal Windows Platform, visionOS, Dedicated Server, sistem embedded (Embedded Linux dan QNX), serta XR. Platform tertutup seperti konsol tersedia bagi pengembang yang punya akses dari pemilik platform. |
| Akses kode sumber | Tertutup untuk umum. Unity menawarkan **Source Code Access**, yang termasuk dalam paket Unity Enterprise, dan **Source Code Adapt** untuk merilis game dengan kode engine yang sudah diubah. |
| Cocok untuk tim yang | Ingin memakai C#, mengerjakan 2D dan 3D di alat yang sama, menargetkan banyak platform termasuk mobile dan XR, dan mau memakai aset atau alat siap pakai dari toko aset. |
| Ekosistem | Unity Asset Store (aset 3D, 2D, audio, dan alat editor), paket resmi lewat Package Manager, serta manual dan Script Reference yang dipisah per versi. |
| Dipakai untuk | *V Rising* (Stunlock Studios), disebut di halaman Unity Source Code sebagai contoh studio yang memakai DOTS dan akses kode sumber. |

Dokumentasi Unity dipisah per versi, dan alamatnya memuat nomor versi seperti `6000.0`. Daftar platform di atas diambil dari manual 6.0. Versi lain bisa punya daftar yang berbeda.

## Unreal Engine

Unreal Engine adalah engine dari Epic Games. Logika game ditulis dengan C++ atau Blueprint, dan dunia game disusun dari Actor beserta komponennya.

| Kriteria | Unreal Engine |
| --- | --- |
| Bahasa scripting | C++, dan Blueprint sebagai sistem pemrograman visual. |
| Model scene | [Actor dan komponen](/belajar/lanskap-engine/01-apa-itu-engine/#actor-dan-komponen). |
| Editor dan alur kerja | Unreal Editor dengan panel Outliner dan Details. Game diuji di editor, lalu dipaketkan per platform ([Pelajaran 1](/belajar/lanskap-engine/01-apa-itu-engine/#runtime-dan-editor-apa-yang-ikut-ke-build)). |
| 2D dan 3D | Alat dan fiturnya terutama untuk 3D. Ada plugin Paper2D untuk game 2D berbasis sprite. |
| Platform target | Windows, macOS, Linux, iOS, dan Android. Konsol tersedia bagi pengembang yang disetujui pemilik platform. |
| Akses kode sumber | Source available: kode sumbernya bisa dibaca dan diubah setelah kamu menyetujui perjanjian lisensinya (EULA), tetapi lisensinya bukan lisensi open source. |
| Cocok untuk tim yang | Mengerjakan game 3D, menguasai C++ atau mau memakai Blueprint, dan butuh kemungkinan membaca atau mengubah kode engine. |
| Ekosistem | Toko aset Fab, plugin, dan dokumentasi resmi Epic. |
| Dipakai untuk | |

Untuk Unreal, cocokkan setiap baris dengan dokumentasi Epic untuk versi yang kamu pakai. Nama panel dan cara membuat build bisa berubah antarversi.

## Godot

Godot adalah engine open source yang dikembangkan komunitas dan dinaungi Godot Foundation. Dunia game disusun sebagai pohon node, dan logika ditulis dengan GDScript, C#, atau C++.

| Kriteria | Godot |
| --- | --- |
| Bahasa scripting | GDScript, C#, dan C++ adalah bahasa yang didukung resmi. Bahasa lain bisa ditambahkan pihak ketiga lewat GDExtension. Proyek C# di Godot 4 belum bisa diekspor ke web. |
| Model scene | [Pohon node](/belajar/lanskap-engine/01-apa-itu-engine/#pohon-node), dengan scene yang bisa dipasang di scene lain. |
| Editor dan alur kerja | Editor dengan Scene dock, editor skrip bawaan (editor luar seperti Visual Studio Code juga didukung), debugger, profiler, dan pengeditan scene saat game berjalan. Skrip `@tool` bisa berjalan di editor. Editor berjalan di Windows, macOS, dan Linux; versi Android dan web masih eksperimental. |
| 2D dan 3D | Keduanya. Fitur 2D punya node dan alat sendiri (misalnya cahaya dan bayangan 2D). Untuk 3D ada tiga [renderer](/kamus/dasar/renderer/): Forward+, Mobile, dan Compatibility. |
| Platform target | Windows, macOS, Linux, *BSD, Android, iOS, dan Web. Godot Foundation tidak merawat port konsol resmi. Pengembang yang disetujui pemilik platform memakai middleware dari pihak ketiga atau membangun export template sendiri dengan SDK resmi. |
| Akses kode sumber | Open source, lisensi MIT. |
| Cocok untuk tim yang | Ingin bisa membaca dan mengubah kode engine tanpa perjanjian tambahan, mengerjakan 2D atau 3D, dan, jika menargetkan konsol, siap bekerja dengan penyedia port pihak ketiga. |
| Ekosistem | Asset Store resmi (masih beta), yang bisa dibuka dari tab Asset Store di editor dan di Project Manager. Asset Store adalah penerus Asset Library. Menurut FAQ-nya, aset belum bisa dijual di sana, tetapi fitur itu sudah direncanakan. Asset Library lama masih bisa diakses, dan semua asetnya gratis dengan lisensi open source. Dokumentasi resmi dengan Manual dan Class reference. |
| Dipakai untuk | *Brotato* (Blobfish) dan *Dome Keeper* (Bippinbits), tercantum di halaman Showcase situs Godot. |

Lisensi MIT juga punya akibat praktis: game yang dirilis wajib menyertakan pemberitahuan hak cipta dan teks lisensi Godot. Dokumentasi Godot punya halaman khusus tentang cara memenuhinya.

## GameMaker

GameMaker adalah engine untuk game 2D dari YoYo Games, yang kini menjadi bagian dari Opera. Logika ditulis dengan GameMaker Language (GML), bahasa milik GameMaker sendiri.

| Kriteria | GameMaker |
| --- | --- |
| Bahasa scripting | GML, dalam dua bentuk: **GML Visual** yang menyusun blok aksi, dan **GML Code** yang ditulis manual. |
| Model scene | Sprite, object, dan room. Object memberi respons terhadap event (misalnya setiap Step, yaitu satu frame), lalu instance dari object itu ditaruh di room. Model ini dekat dengan [GameObject dan komponen](/belajar/lanskap-engine/01-apa-itu-engine/#gameobject-dan-komponen) dalam hal satu objek memegang data dan logikanya, tetapi kemampuannya datang dari event, tanpa komponen yang dipasang. |
| Editor dan alur kerja | Satu IDE berisi Asset Browser dan editor untuk setiap jenis aset: sprite, object, room, tileset, dan lainnya. |
| 2D dan 3D | Ditujukan untuk 2D. Manual juga menyediakan fungsi primitive dan vertex buffer yang bisa dipakai untuk menggambar 3D lewat kode. |
| Platform target | Situs GameMaker menyebut Windows, Mac, Linux, Android, iOS, HTML5, Xbox Series X\|S, PlayStation 5, dan Nintendo Switch, serta GX.games. Ekspor konsol hanya tersedia di paket tertentu, dan tetap butuh persetujuan pemilik platform. |
| Akses kode sumber | Tertutup untuk umum. Halaman paket GameMaker mencantumkan akses kode sumber di paket Enterprise. |
| Cocok untuk tim yang | Fokus pada game 2D, ingin satu alat terpadu dari gambar sampai build, dan punya anggota yang lebih nyaman mulai dari blok visual sebelum menulis kode. |
| Ekosistem | GameMaker Marketplace (aset, ekstensi, shader, template proyek, tutorial), manual resmi, dan Asset Bundles. |
| Dipakai untuk | *UNDERTALE* dan *Hyper Light Drifter*, disebut di halaman depan gamemaker.io. |

GameMaker punya dua jalur rilis: LTS yang jarang diperbarui dan hanya mendapat perbaikan bug penting, serta Beta yang diperbarui sering. Manual yang dikutip di sini adalah cabang monthly, jadi cek apakah fitur yang kamu baca sudah ada di jalur yang kamu pasang.

## Framework dan library web

Untuk game yang berjalan di browser, banyak tim memakai library atau framework JavaScript. Seperti dibahas di [Pelajaran 1](/belajar/lanskap-engine/01-apa-itu-engine/#library-framework-dan-engine), alat-alat ini berbeda dalam hal siapa yang memegang game loop dan alat apa yang ikut disediakan. Empat contoh berikut sering dipakai dan masing-masing menyebut dirinya dengan istilah berbeda.

| Kriteria | Three.js | Phaser | PlayCanvas | Babylon.js |
| --- | --- | --- | --- | --- |
| Menyebut dirinya | Library 3D JavaScript | Framework game HTML5 | Engine game open source | Engine rendering web |
| Bahasa scripting | JavaScript | JavaScript atau TypeScript | JavaScript atau TypeScript | JavaScript atau TypeScript |
| Model scene | Scene graph: objek ditambahkan ke `Scene` dan bisa punya anak | Scene berisi Game Object | Entity dengan komponen yang dipasang (`addComponent`) | Scene berisi mesh, kamera, dan cahaya |
| Editor dan alur kerja | Kode; ada editor daring di threejs.org | Kode, dengan template proyek dari `create-phaser-game` | Kode, atau PlayCanvas Editor berbasis browser | Kode, dengan Playground, Sandbox, dan Node Material Editor daring |
| 2D dan 3D | 3D, dengan renderer [WebGL](/kamus/web/webgl/) dan WebGPU | 2D, dengan rendering WebGL dan Canvas | 2D dan 3D, di atas WebGL2 dan WebGPU | 3D |
| Platform target | Browser | Browser; README menyebut iOS, Android, Steam, dan aplikasi native lewat alat pihak ketiga | Browser | Browser; Babylon Native untuk aplikasi native |
| Akses kode sumber | Open source, MIT | Open source, MIT | Open source, MIT (engine dan editor) | Open source, Apache 2.0 |
| Ekosistem | Paket npm, contoh, forum, Discord | Paket npm, lebih dari 2.000 contoh kode, forum, Discord | Paket npm, paket React dan Web Components, forum | Paket npm, Playground, forum |

Satu profil untuk keempatnya, dengan baris kecocokan tim dan contoh game:

- **Cocok untuk tim yang** butuh game bisa dimainkan langsung di browser tanpa instalasi, menguasai JavaScript atau TypeScript beserta alat seperti npm dan Vite, dan siap menyusun sendiri bagian yang tidak disediakan, seperti editor level atau pipeline aset.
- **Dipakai untuk:** tidak dicantumkan. README resmi keempatnya menautkan demo dan galeri proyek, tetapi tidak menyebut judul game tertentu yang bisa dijadikan contoh di sini.

[Three.js](/kamus/web/threejs/) dipakai di Bab Tambahan [Web & Three.js](/belajar/web-threejs/01-frame/), jadi kamu bisa melihat langsung seperti apa bekerja dengan library yang tidak memegang game loop.

## Cara membaca tabel

Tabel ini tidak punya kolom pemenang. Setiap sel menjawab pertanyaan tentang fakta, dan fakta itu baru berarti setelah dicocokkan dengan proyekmu. Urutan berikut membantu:

1. **Tulis dulu syarat yang tidak bisa ditawar.** Misalnya "harus bisa dimainkan di browser" atau "harus rilis di konsol". Syarat seperti ini langsung mencoret beberapa kolom.
2. **Periksa kombinasi baris, tidak hanya satu baris.** Godot mendukung C# dan mendukung web, tetapi proyek C# di Godot 4 belum bisa diekspor ke web. Kesimpulan yang benar baru muncul saat dua baris dibaca bersama.
3. **Bedakan "bisa" dan "disediakan".** GameMaker bisa menggambar 3D lewat kode, tetapi editornya ditujukan untuk 2D. Three.js bisa dipakai untuk game, tetapi editor level dan pipeline aset harus kamu siapkan sendiri.
4. **Baca sumbernya untuk versi yang kamu pakai.** Sel di tabel ini adalah ringkasan per 30 Oktober 2026. Setiap profil menyebut versi dokumentasi yang dibaca.
5. **Lisensi dan biaya punya pelajaran sendiri.** Baris kode sumber hanya menjelaskan siapa yang boleh membaca dan mengubah engine. Ketentuan biaya dibahas di [Pelajaran 3](/belajar/lanskap-engine/03-lisensi/).

Cara menimbang kriteria-kriteria ini terhadap genre, ukuran tim, dan keahlian anggotanya dibahas di [Pelajaran 4, Kriteria memilih engine](/belajar/lanskap-engine/04-kriteria-memilih/).

## Kesalahan umum

### Menyamakan "bisa dibuka kodenya" dengan "open source"

```text title="✗ Keliru"
kode engine bisa dibaca  →  engine ini open source  →  boleh diubah dan dibagikan bebas
```

```text title="✓ Benar"
kode engine bisa dibaca  →  cek nama lisensinya
    MIT, Apache 2.0, dan sejenisnya  →  open source, ikuti syarat lisensinya
    perjanjian atau EULA khusus       →  source available, ikuti isi perjanjiannya
```

Engine yang kodenya bisa diakses lewat perjanjian punya aturan sendiri tentang siapa yang boleh melihat, mengubah, dan membagikan kodenya. Nama lisensinya yang menentukan.

### Mengira dukungan platform di daftar fitur berarti siap rilis

```text title="✗ Keliru"
daftar platform engine menyebut konsol  →  tinggal klik build di akhir proyek
```

```text title="✓ Benar"
awal proyek:  daftar sebagai pengembang di pemilik platform, cek syarat ekspor engine
selama produksi:  uji di perangkat pengembangan, bukan hanya di PC
```

Konsol butuh persetujuan, SDK, dan perangkat khusus. Di sebagian engine, ekspor konsol juga lewat pihak ketiga atau paket tertentu. Semua itu makan waktu, jadi perlu diurus jauh sebelum rilis.

### Membandingkan engine dengan ukuran yang berbeda-beda

```text title="✗ Keliru"
Engine A: "grafisnya bagus"
Engine B: "mudah dipelajari"
Engine C: "gratis"
```

```text title="✓ Benar"
Engine A, B, C: bahasa, model scene, editor, 2D/3D, platform, kode sumber, tim, ekosistem, contoh
```

Kesan dari ulasan atau video biasanya menyorot hal yang berbeda untuk setiap engine, jadi tidak bisa dibandingkan. Isi sembilan baris yang sama untuk setiap pilihan, dari sumber resmi.

### Membaca dokumentasi versi lain

```text title="✗ Keliru"
engine terpasang: versi lama
dokumentasi dibuka: versi terbaru, fiturnya dikira tersedia
```

```text title="✓ Benar"
cek nomor versi di alamat atau pemilih versi dokumentasi, samakan dengan versi engine-mu
```

Daftar platform, bahasa, dan fitur berubah antarversi. Contohnya di pelajaran ini: dukungan C# untuk web berbeda antara Godot 3 dan Godot 4.
