## Gambaran besar

<Aside type="note" title="Model mental: alamat yang relatif">
"Gelas ada di atas meja, meja ada di dapur, dapur ada di rumah nomor 5." Setiap alamat ditulis relatif terhadap tempat yang lebih besar. Saat rumahnya dipindah, kamu tidak perlu menulis ulang letak gelas: gelas tetap di atas meja, dan meja tetap di dapur.
</Aside>

Di [Pelajaran 1](/belajar/fondasi-engine/01-frame/), kamu memutar kubus setiap frame. Pelajaran ini menjawab pertanyaan berikutnya: **di mana** kubus itu berada, **menghadap ke mana**, dan **relatif terhadap apa**.

Setiap objek di dunia 3D menyimpan tiga hal: posisi, rotasi, dan skala. Ketiganya disebut [transform](/kamus/ruang/transform/), dan nilainya selalu relatif terhadap induk objek itu, persis seperti alamat gelas tadi.

Contoh pertama: objek yang bergerak lurus menuju target, berhenti tepat di target, dengan kecepatan tetap per detik.

<EngineTabs>
<div slot="unity">

```csharp title="Kejar.cs"
using UnityEngine;

public class Kejar : MonoBehaviour
{
    public Transform target;
    public float kecepatan = 3f; // meter per detik

    void Update()
    {
        // position = posisi dunia. MoveTowards tidak pernah melewati target.
        transform.position = Vector3.MoveTowards(
            transform.position, target.position, kecepatan * Time.deltaTime);
    }
}
```

</div>
<div slot="unreal">

```cpp title="Kejar.cpp"
// Target (AActor*) dan Kecepatan (float) dideklarasikan sebagai UPROPERTY di Kejar.h
void AKejar::Tick(float DeltaSeconds)
{
    Super::Tick(DeltaSeconds);
    const FVector Sekarang = GetActorLocation();       // posisi dunia
    const FVector Tujuan = Target->GetActorLocation();
    // Kecepatan dalam unit Unreal (sentimeter) per detik
    SetActorLocation(FMath::VInterpConstantTo(Sekarang, Tujuan, DeltaSeconds, Kecepatan));
}
```

</div>
<div slot="godot">

```gdscript title="kejar.gd"
extends Node3D

@export var target: Node3D
@export var kecepatan := 3.0 # meter per detik

func _process(delta: float) -> void:
    # global_position = posisi dunia. move_toward tidak pernah melewati target.
    global_position = global_position.move_toward(target.global_position, kecepatan * delta)
```

</div>
</EngineTabs>

Ketiga contoh membaca dan menulis posisi **dunia**, bukan posisi lokal. Alasannya dibahas di bagian Local dan world.

## Koordinat: tiap engine punya arah sendiri

Setiap titik ditulis dengan tiga angka: X, Y, dan Z. Semua engine memakai tiga sumbu, tetapi [arah sumbu dan satuannya](/kamus/ruang/coords/) berbeda:

| | Sumbu atas | Sumbu depan | Tangan | Satu unit |
| --- | --- | --- | --- | --- |
| Unity | +Y | +Z | kiri | 1 meter |
| Unreal | +Z | +X | kiri | 1 sentimeter |
| Godot | +Y | −Z | kanan | 1 meter |

Perbedaan ini terasa saat memindahkan aset atau angka antar-engine. Karakter setinggi 2 unit di Unity berarti 2 meter, tetapi di Unreal hanya 2 sentimeter. Model dari Blender (Z ke atas) juga perlu diputar saat diimpor ke engine yang memakai Y ke atas, dan importer engine biasanya melakukannya otomatis.

Arah "depan" di Godot adalah −Z, tetapi model 3D yang diimpor dianggap menghadap +Z. Itu sebabnya `look_at()` punya opsi `use_model_front`.

## Transform: posisi, rotasi, dan skala

Transform berisi tiga bagian:

- **Posisi**: di mana objek berada. Satu [vektor](/kamus/ruang/vector/) X, Y, Z.
- **Rotasi**: ke mana objek menghadap.
- **Skala**: seberapa besar objek dibanding ukuran aslinya. Skala 1 berarti ukuran asli.

Engine menerapkannya dengan urutan skala, lalu rotasi, lalu posisi. Karena itu objek membesar dan berputar di sekitar titik pusatnya sendiri, bukan di sekitar titik nol dunia.

<EngineTabs>
<div slot="unity">

Setiap GameObject punya komponen **Transform** dengan `position`, `rotation`, dan `localScale`. Nilai di Inspector adalah nilai **lokal**, relatif terhadap induk.

</div>
<div slot="unreal">

`FTransform` berisi **Location**, **Rotation**, dan **Scale3D**. Panel Details sebuah Actor menampilkan ketiganya.

</div>
<div slot="godot">

Node3D punya `position`, `rotation`, dan `scale`, digabung dalam satu nilai `transform` bertipe `Transform3D`. Nilai di Inspector juga relatif terhadap induk.

</div>
</EngineTabs>

Hindari skala 0 di sumbu mana pun. Perhitungan matriksnya menjadi tidak valid dan bisa menghasilkan nilai NaN yang merusak objek lain di sekitarnya.

## Rotasi: derajat, radian, dan quaternion

Cara paling mudah dibaca untuk menulis rotasi adalah **sudut Euler**: tiga sudut, satu untuk setiap sumbu. Masalahnya, saat dua sumbu putar menjadi segaris, satu arah putaran hilang. Kondisi ini disebut **gimbal lock**. Karena itu engine menyimpan rotasi sebagai [quaternion](/kamus/ruang/quaternion/), empat angka yang tidak mengalami gimbal lock dan bisa diinterpolasi dengan mulus.

Kamu hampir tidak pernah mengisi angka quaternion secara manual. Engine menyediakan fungsi untuk membuatnya dari sudut Euler, dari sumbu dan sudut, atau dari arah yang ingin dihadap.

Yang perlu diperhatikan adalah **satuan sudutnya**:

<EngineTabs>
<div slot="unity">

`transform.rotation` bertipe `Quaternion`. Untuk sudut yang mudah dibaca, pakai `transform.eulerAngles` atau `Quaternion.Euler(x, y, z)`, keduanya dalam **derajat**.

```csharp
transform.rotation = Quaternion.Euler(0f, 90f, 0f); // menghadap 90° ke kanan
```

</div>
<div slot="unreal">

Editor dan `FRotator` memakai **derajat** dengan urutan (Pitch, Yaw, Roll). Untuk perhitungan rotasi di C++, tersedia `FQuat`.

```cpp
SetActorRotation(FRotator(0.f, 90.f, 0.f)); // Yaw 90°
```

</div>
<div slot="godot">

Properti `rotation` memakai **radian**. Untuk derajat, pakai `rotation_degrees`, atau ubah dulu dengan `deg_to_rad()`. Rotasi yang sama juga tersedia sebagai `quaternion`.

```gdscript
rotation_degrees.y = 90.0          # derajat
rotation.y = deg_to_rad(90.0)      # sama, ditulis dalam radian
```

Dokumentasi Godot menyarankan sudut Euler hanya untuk editor dan rotasi sederhana. Untuk rotasi yang rumit, pakai `Basis` atau `Quaternion`.

</div>
</EngineTabs>

Satu radian kira-kira 57,3 derajat, dan satu putaran penuh = 2π radian. Penjelasan lengkapnya ada di [Radian & Sudut Euler](/kamus/ruang/radian/).

## Induk dan anak

Objek bisa menjadi anak objek lain. Transform anak dihitung relatif terhadap induknya, sehingga jika induk bergeser, berputar, atau membesar, semua anaknya ikut. Satu induk boleh punya banyak anak, tetapi setiap anak hanya punya satu induk. Susunan ini disebut [hierarki](/kamus/ruang/hierarchy/).

<Demo name="hierarchy" caption="Tampak atas. Putar dan geser induk: posisi lokal anak tetap, posisi dunianya berubah." />

Hierarki dipakai di hampir semua game:

- Senjata menjadi anak dari tangan karakter, sehingga ikut setiap gerakan animasi.
- Kamera orang ketiga menjadi anak dari objek kosong di belakang pemain.
- Roda menjadi anak dari mobil. Mobil bergerak maju, roda berputar di tempatnya sendiri.

Objek kosong yang tidak terlihat sering dipakai sebagai induk, berfungsi seperti engsel. Induk kosong biasanya dibiarkan berskala 1. Induk yang diskalakan tidak seragam (misalnya X dua kali lipat) bisa membuat anak yang berputar tampak miring atau gepeng. Dokumentasi Godot juga menyarankan untuk tidak menskalakan node yang akan digerakkan atau diputar, tetapi menskalakan anaknya.

Saat memindahkan objek ke induk baru, ada dua pilihan: pertahankan posisi **dunia** (objek tetap di tempatnya) atau pertahankan nilai **lokal** (objek bisa melompat, karena nilainya kini dihitung dari induk baru).

<EngineTabs>
<div slot="unity">

`transform.SetParent(induk)` mempertahankan posisi, rotasi, dan skala dunia, karena argumen `worldPositionStays` bawaannya `true`. Isi `false` untuk mempertahankan nilai lokal.

</div>
<div slot="unreal">

`AttachToActor` atau `AttachToComponent` dengan `FAttachmentTransformRules`, misalnya `KeepWorldTransform` atau `KeepRelativeTransform`.

</div>
<div slot="godot">

`anak.reparent(induk_baru)` mempertahankan transform dunia, karena `keep_global_transform` bawaannya `true`. Sementara itu, `induk.add_child(anak)` mempertahankan nilai lokal anak.

</div>
</EngineTabs>

## Local dan world

**Local space** adalah koordinat relatif terhadap induk. **World space** adalah koordinat akhir di dunia, setelah semua transform induknya diterapkan. Objek tanpa induk punya nilai lokal yang sama dengan nilai dunianya. [Penjelasan lengkap](/kamus/ruang/local-world/).

<EngineTabs>
<div slot="unity">

| | Lokal | Dunia |
| --- | --- | --- |
| Posisi | `localPosition` | `position` |
| Rotasi | `localRotation` | `rotation` |
| Skala | `localScale` | `lossyScale` (hanya baca) |

Mengubah titik antar-ruang: `TransformPoint()` (lokal ke dunia) dan `InverseTransformPoint()` (dunia ke lokal).

</div>
<div slot="unreal">

Pada komponen: `GetRelativeLocation()` (relatif ke induk) dan `GetComponentLocation()` (dunia). Pada Actor: `GetActorLocation()` (dunia).

</div>
<div slot="godot">

| | Lokal | Dunia |
| --- | --- | --- |
| Posisi | `position` | `global_position` |
| Transform lengkap | `transform` | `global_transform` |

Mengubah titik antar-ruang: `to_global()` (lokal ke dunia) dan `to_local()` (dunia ke lokal). Fungsi `rotate()` memutar relatif terhadap induk. Untuk memutar pada sumbu objek sendiri, pakai `rotate_object_local()`.

</div>
</EngineTabs>

Aturan praktisnya: saat membandingkan dua objek yang punya induk berbeda, misalnya menghitung jarak musuh ke pemain, pakai nilai **dunia** keduanya.

## Matematika gerak: arah, jarak, dan target

Hampir semua gerakan dibangun dari beberapa operasi [vektor](/kamus/ruang/vector/):

```text title="Pseudocode: menuju target"
selisih = posisi_target - posisi        // vektor dari kita ke target
jarak   = panjang(selisih)
arah    = normalisasi(selisih)          // panjangnya 1, hanya berisi arah

posisi  = posisi + arah * kecepatan * delta
```

[Normalisasi](/kamus/ruang/normalize/) membuat panjang vektor menjadi 1 tanpa mengubah arahnya. Langkah ini penting. Tanpanya, objek yang jauh dari target bergerak lebih cepat daripada objek yang dekat, karena selisihnya lebih panjang.

<EngineTabs>
<div slot="unity">

`Vector3.Distance(a, b)` untuk jarak, `selisih.normalized` untuk arah (menghasilkan vektor nol jika selisihnya terlalu kecil). Arah depan objek di ruang dunia: `transform.forward`, yaitu sumbu biru (Z) yang sudah ternormalisasi.

</div>
<div slot="unreal">

`FVector::Dist(A, B)` untuk jarak, `Selisih.GetSafeNormal()` untuk arah. Arah depan Actor: `GetActorForwardVector()`, yaitu sumbu +X.

</div>
<div slot="godot">

`a.distance_to(b)` untuk jarak, `a.direction_to(b)` untuk arah (sama dengan `(b - a).normalized()`). Arah depan node di ruang dunia: `-global_transform.basis.z`, karena depan adalah −Z.

</div>
</EngineTabs>

Untuk mengetahui apakah sesuatu ada di depan atau di belakang, pakai [dot product](/kamus/ruang/dot/) antara arah depan objek dan arah ke target. Untuk dua arah yang sudah dinormalisasi, hasilnya mendekati 1 jika searah, 0 jika tegak lurus, dan negatif jika target ada di belakang.

```text title="Pseudocode: apakah pemain terlihat dari depan?"
arah_ke_pemain = normalisasi(posisi_pemain - posisi_musuh)
if dot(depan_musuh, arah_ke_pemain) > 0.5:   // kira-kira dalam sudut 60° dari depan
    kejar_pemain()
```

## Kesalahan umum

### Derajat dimasukkan ke properti radian

```gdscript title="✗ Keliru (Godot)"
rotation.y = 90          # 90 radian, sekitar 5157°
```

```gdscript title="✓ Benar"
rotation_degrees.y = 90
```

Periksa satuan sudut setiap kali memakai API rotasi baru, terutama saat pindah engine.

### Bergerak serong lebih cepat

```text title="✗ Keliru"
arah = Vector3(input_x, 0, input_z)     // (1, 0, 1) saat dua tombol ditekan
posisi += arah * kecepatan * delta
```

```text title="✓ Benar"
arah = normalisasi(Vector3(input_x, 0, input_z))
posisi += arah * kecepatan * delta
```

Panjang (1, 0, 1) adalah √2 ≈ 1,41, jadi tanpa normalisasi karakter 41% lebih cepat saat bergerak serong. Di Godot, `Input.get_vector()` sudah mengembalikan vektor dengan panjang maksimum 1.

### Mencampur posisi lokal dan dunia

```text title="✗ Keliru"
jarak = panjang(pemain.posisi_lokal - musuh.posisi_dunia)
```

```text title="✓ Benar"
jarak = panjang(pemain.posisi_dunia - musuh.posisi_dunia)
```

Hasilnya tampak benar selama induk pemain berada di titik nol, lalu tiba-tiba salah saat induknya dipindahkan.

### Menskalakan induk yang diputar

```text title="✗ Keliru"
Mobil (skala 2, 1, 1)
└── Roda (berputar)          // tampak gepeng saat berputar
```

```text title="✓ Benar"
Mobil (skala 1)
├── Badan (skala 2, 1, 1)
└── Roda (berputar)
```

Taruh skala pada anak yang tidak punya keturunan, bukan pada induk yang menggerakkan anak lain.

### Menyalin angka posisi antar-engine

```text title="✗ Keliru"
// Unity (0, 2, 5)  →  Unreal (0, 2, 5)
```

```text title="✓ Benar"
// Unity (x=0, y=2, z=5) meter  →  Unreal (X=500, Y=0, Z=200) sentimeter
```

Satuannya dikali 100, dan sumbunya ditukar: atas Unity (Y) menjadi Z di Unreal, depan Unity (Z) menjadi X di Unreal.
